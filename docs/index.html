An honest security model

What clipguard protects, and what it doesn't. Full details in the README.

Protected

  • Every clip encrypted with AES-256-GCM and bound to its row, so tampering is detected.
  • Random master key kept only in Windows Credential Manager, macOS Keychain or Linux Secret Service. No keystore, no start: never a key file.
  • Deleted clips overwritten on disk. Unix permissions 0600/0700.
  • Password-manager markers honoured on all three platforms.
  • No network code at all.

Not protected

  • Malware running as your user can ask the keystore for the key, just like clipguard does.
  • Timestamps and pin/secret flags stay readable, so cleanup works without decrypting.
  • Secret detection is pattern-based: unknown formats are stored as normal clips.

Download

Latest release from GitHub.

Windows

Installer (.msi) x64 Portable (.zip) no install 
msiexec /i clipguard-<version>-x64.msi /qn

Not code-signed yet: SmartScreen may warn. More info → Run anyway.

macOS

Apple Silicon (.tar.gz) arm64 
tar -xzf clipguard-*-macos-arm64.tar.gz
xattr -d com.apple.quarantine clipguard
./clipguard

Auto-paste needs Accessibility permission.

Linux

x64 (.tar.gz) X11 
tar -xzf clipguard-*-linux-x64.tar.gz
./clipguard

Needs a Secret Service keyring (GNOME Keyring, KWallet, KeePassXC).

Verify downloads with SHA256SUMS.txt.
